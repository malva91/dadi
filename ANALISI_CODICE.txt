1. PROBLEMI CRITICI DI STABILITÀ
================================================================================

1.1 RACE CONDITIONS negli Effetti
----------------------------------
FILE: effects-engine.js
PROBLEMA: checkForEffects può essere chiamato prima che loadConfiguration finisca
RISCHIO: Regole effetti non caricate, risultati errati
SOLUZIONE: Già presente ensureConfigLoaded() ma NON sempre usata in main.js

CODICE PROBLEMATICO:
- main.js:573 - rollAllDice chiama effectsEngine.checkForEffects SENZA await
- ui-renderer.js:177 - Usa effectsEngine senza verificare se è pronto

FIX NECESSARIO:
  await this.effectsEngine.ensureConfigLoaded();
  prima di OGNI chiamata a checkForEffects

1.2 LISTENER DUPLICATI
-----------------------
FILE: main.js, room-service.js, chat-service.js
PROBLEMA: Listener Firebase non sempre rimossi correttamente
RISCHIO: Memory leak, eventi multipli

CODICE PROBLEMATICO:
- main.js:349 - setupFirebaseListeners crea listener ma cleanup incompleto
- room-service.js:126 - heartbeatInterval non sempre clearato
- chat-service.js:92 - listeners array ma cleanup condizionale

FIX NECESSARIO:
  Usare SEMPRE try-catch in cleanup
  Verificare che ref esista prima di .off()

1.3 MEMORY LEAK PARTICELLE
---------------------------
FILE: particle-pool.js, effects-engine.js
PROBLEMA: activeParticles può crescere indefinitamente
RISCHIO: Rallentamento progressivo dell'app

CODICE PROBLEMATICO:
- particle-pool.js:23 - getParticle crea illimitate particelle oltre maxSize*2
- effects-engine.js:354 - createParticles non verifica limite globale

FIX NECESSARIO:
  Limite HARD su particelle totali
  Cleanup automatico ogni N secondi

1.4 FIRESTORE vs RTDB CONFUSIONE
---------------------------------
FILE: Multipli
PROBLEMA: Dati sparsi tra Firestore E Realtime Database
RISCHIO: Inconsistenze, complessità inutile

DISTRIBUZIONE ATTUALE:
- Firestore: effectsConfig, effectRules, presets, customDiceTypes
- RTDB: rooms, users, chat, diceResults, extractionState

PROBLEMA: Perché non tutto su Firestore? RTDB serve SOLO per real-time
SOLUZIONE: Migrare config statiche a RTDB per coerenza OPPURE tutto su Firestore

2.1 VALIDAZIONE HTML DUPLICATA
-------------------------------
FILE: validation.js
PROBLEMA: escapeHtml() E sanitizeInput() fanno la stessa cosa

  div.textContent = text
  return div.innerHTML

sanitizeInput:
  replace /</g, '&lt;'
  replace />/g, '&gt;'

3. MANCANZA DI CENTRALIZZAZIONE
================================================================================

3.1 PALETTE COLORI
------------------
ATTUALE: Hardcoded in constants.js
PROBLEMA: Per aggiungere colore serve modificare constants.js
SOLUZIONE: Array in config-registry.js

PRIMA:
  const CONSTANTS = {
    COLOR_PALETTE: ['#8B3A3A', ...]
  }

DOPO:
  configRegistry.addToArray('COLOR_PALETTE', '#NUOVO_COLORE');


3.2 DICE COLORS
---------------
ATTUALE: Classe ColorTypesRegistry con initializeDefaultColors()
PROBLEMA: Per aggiungere colore serve modificare la classe
SOLUZIONE: Array in config-registry.js

    initializeDefaultColors() {
      this.registerColor({id: 'rosso', ...})
    }
  }

DOPO:
  configRegistry.get('DICE_COLORS').push({
    id: 'verde', label: 'Verde', emoji: '🟢', visible: true
  });
